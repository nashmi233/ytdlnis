# توقيع حمّل والتحديث مع الاحتفاظ بالبيانات

يتحقق أندرويد من توقيع التطبيق قبل تثبيت التحديث فوق النسخة السابقة. يجب الاحتفاظ بمفتاح التوقيع الخاص خارج المستودع العام، واستخدامه في كل إصدار لاحق. لا تكفي شهادة التوقيع العامة الموجودة داخل APK لاستعادة المفتاح الخاص.

## حالة الإصدارات التجريبية القديمة

استخدمت إصدارات الاختبار السابقة مفاتيح Debug مؤقتة مختلفة على خوادم GitHub Actions. لم يُحفظ المفتاح الخاص المستخدم لنسخة 1.8.9.6 ضمن ملفات المشروع أو مخرجات البناء المتاحة. لذلك لا تُقدّم نسخة جديدة بتوقيع مختلف على أنها تحديث متوافق معها، ولا يُطلب حذف التطبيق أو بياناته لتجاوز هذا القيد.

بصمة شهادة نسخة 1.8.9.6 المنشورة (SHA-256):
`b468dc996bf484db7cdbac5871042bc00d2844c4898990f5b520d5876840b051`

عُثر أيضًا على أرشيف مفتاح مطور قديم محفوظ خارج المستودع، لكن بصمته لا تطابق ملف 1.8.9.2 المتاح ولا الإصدارات التجريبية الأخيرة، ولذلك لا يُستخدم لإثبات توافق التحديث معها.

## بناء إصدار توزيع

اعتبارًا من تعديلات 1.8.9.7، يرفض بناء Release الرجوع إلى مفتاح Debug تلقائي. تُوفّر إعدادات المفتاح المحفوظ عبر بيئة بناء موثوقة:

- `HAMMEL_KEYSTORE_PATH`
- `HAMMEL_STORE_PASSWORD`
- `HAMMEL_KEY_ALIAS`
- `HAMMEL_KEY_PASSWORD`

أو عبر ملف `keystore.properties` المحلي المستثنى من Git. لا تُرفع ملفات المفاتيح أو كلمات مرورها إلى المستودع أو مخرجات Actions العامة.

قبل نشر تحديث متوافق، يجب مقارنة توقيع APK مع النسخة السابقة واختبار التثبيت فوقها مع الاحتفاظ ببيانات تجريبية. نجاح بناء APK وحده لا يثبت توافق التحديث. بناء Debug في CI مخصص للفحص فقط ولا يُنشر للمستخدمين كتحديث.

التحديث داخل التطبيق موجود ويتحقق من اسم الحزمة ورقم الإصدار والتوقيع قبل فتح مُثبّت أندرويد. يبقى تأكيد التثبيت من المستخدم مطلوبًا؛ التطبيق لا يستبدل نفسه بصمت.
